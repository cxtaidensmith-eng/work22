项目默认快速实验规则
日期：2026-08-05

目标：避免等待约半小时后才发现单折结果无效，同时不牺牲最终候选的历史可比性。

一、运行时间门禁

1. 正式或筛选训练必须使用 CUDA；禁止静默回退 CPU。
2. 启动时确认模型、输入和 criterion 均在 CUDA。
3. 在前 10 个 epoch 自动估算 400 epoch 总用时。
4. 如果预计单折超过 5 分钟，立即停止并检查 device、逐 epoch 诊断和 CPU/GPU 同步，不继续等待半小时。
5. 输出 epoch 10、50、100、200、300 的进度与剩余时间估计。

二、探索模型采用连续分段预算

同一次训练连续执行，不重新初始化、不加载 checkpoint：

- 3 epoch：正确性门禁。
- 50 epoch：确认 loss、梯度和指标确实在学习。
- 150 epoch：候选性能门禁。
- 400 epoch：只让通过前面门禁的候选完成。

提前停止只用于候选筛选；被提前停止的结果不得作为正式 400 epoch 结果或论文结论。

建议在 epoch 50 立即停止的情况：

- NaN/Inf；
- 新模块无梯度或表示塌缩；
- loss 基本不下降；
- ACC 长期接近随机水平；
- 明确的实现或 device 异常。

建议在 epoch 150 停止的情况：

- best ACC 比同协议 baseline 的同期曲线低至少两个测试样本；
- Macro-F1、BACC、Macro-AUC 同时没有补偿改善；
- 最近 50 epoch 没有改善趋势；
- 机制诊断与研究假设相反。

边界情况继续到 400 epoch，避免误杀收敛较慢但可能有效的模型。

三、候选数量门禁

1. 每轮先运行一个主候选。
2. 主候选结果明确后，再决定是否触发一个必要对照。
3. 不预先运行全部消融组合。
4. 不重复训练已有 baseline。
5. 只有一个 fold0 胜者进入 10-fold。

四、轻量记录

每 epoch 只记录 loss、learning rate 和五个主指标。

完整梯度、attention、branch similarity、auxiliary 指标只记录：

- epoch 1；
- epoch 50；
- epoch 150；
- epoch 400；
- best checkpoint 回读后。

源码/split/config hash 只在开始和结束检查。每个候选只回读一次 best checkpoint。

五、下一实验默认执行

首先只运行：

Private Query ×3 + Shared Attention + Private FFN ×3。

顺序：

结构审计 -> 3 epoch smoke -> 一次人工确认 -> 50/150/400 连续门禁训练。

若主候选明显失败，立即停止并根据诊断决定是否运行镜像对照；不默认运行其余所有组合。

六、最终正式验证

通过 fold0 筛选的最终候选仍完整运行 400 epoch；进入 10-fold 后不使用性能早停，每折保持历史协议，只在数值、设备或完整性异常时停止。

默认承诺：如果当前 CUDA 环境下预计单折超过 5 分钟，会先停止并报告原因，不让用户无提示地等待约半小时。
